# Аналитика прогона: что куда зашло, что откуда вышло, что сколько стоило

flora записывает в журнал не только «прошёл / не прошёл», но и достаточно, чтобы
разобрать любой прогон по шагам: откуда шаг взял данные, сколько единиц вошло и
вышло, сколько времени и токенов ушло, во сколько это обошлось, какого размера
результат. Это локальная аналитика: никаких внешних сервисов, всё лежит в
`~/.flora/flora.db` и в файлах прогона.

## Что видно и откуда берётся

| Что | Откуда | Что нужно сделать |
|---|---|---|
| Поток данных: какой шаг чем питается | `needs` и все `{{steps.<id>…}}` в шаге, его проверках и ветках | ничего — движок записывает `inputsFrom` сам |
| Что вошло / что вышло (`in → out`) | поле `metrics` в JSON-выводе шага | шаг печатает `"metrics": {"in": 100, "out": 80}` |
| Любые другие счётчики (`attributes`, `rejected`, …) | то же поле `metrics` | добавить числа туда же |
| Размер результата | значение шага по контракту `output` | ничего — считается автоматически |
| Время шага, попытки, ветки | движок | ничего |
| Токены и деньги | харнесс (Claude Code, Codex, Antigravity) или JSON-строка `usage` у `command`-шага | для скрипта: печатать `"usage": {"calls": …, "input_tokens": …, "output_tokens": …, "cost_usd": …}` |

Имена токенов совпадают с семантикой OpenTelemetry для GenAI (`input_tokens` /
`output_tokens`), так что те же числа можно при желании отдавать и в любой
трейсинг.

## Как включить в своём воркфлоу

1. **Шаги связаны через `needs` или ссылки на выводы.** Если шаг читает результат другого шага, укажите это:

   ```yaml
   - id: links
     needs: [concepts]
     executor: { harness: command }
     run: node "{{workflow_dir}}/stage.mjs" --stage 04a --run "{{run}}"
     output: { type: json, schema: { type: object, required: [ok] } }
   ```

   `needs` даёт ребро графа; `{{steps.concepts.output.path}}` в промте или проверке — тоже.

2. **Шаг печатает, что сделал.** Последняя JSON-строка вывода `command`-шага — это его результат по контракту.
   Положите в неё `metrics` и `usage`:

   ```json
   {"stage": "02", "ok": 100, "metrics": {"in": 100, "out": 80, "rejected": 50},
    "usage": {"calls": 3, "input_tokens": 1000, "output_tokens": 200, "cost_usd": 1.25}}
   ```

   `in` и `out` — главные: по ним строится воронка. Остальные ключи в `metrics` — любые числа, которые
   хочется видеть рядом (сколько атрибутов, сколько отклонено, сколько новых сущностей).
   Для шагов Claude Code / Codex / Antigravity токены и цена приходят от самого харнесса, `metrics` можно
   отдавать в JSON-ответе агента точно так же.

3. **Смотреть:**

   ```bash
   flora analytics                       # последний прогон: таблица по шагам и поток
   flora analytics <id> --json           # то же для скриптов
   flora analytics --all                 # по строке на прогон: шаги, время, токены, деньги
   flora analytics --all --workflow nightly-pipeline --csv steps.csv   # для Excel: строка на шаг на прогон
   flora report <id> --out report.md     # документ прогона с разделом Analytics и схемой потока (mermaid)
   flora serve                           # во viewer на странице прогона — блок Analytics: граф + таблица
   ```

   CSV открывается в Excel двойным кликом (UTF-8 с BOM, запятая): колонки `run_id, workflow, run_status,
   started_at, step, title, step_status, harness, from, in, out, metrics, attempts, duration_ms, calls,
   input_tokens, output_tokens, total_tokens, cost_usd, output_bytes` — сводные таблицы по прогонам и
   этапам делаются прямо там.

## Как это читать

- `from` — откуда шаг взял данные. Пусто у первого шага и у шагов, которые ни на кого не ссылаются.
- `in → out` — сколько единиц шаг получил и отдал по его собственному счёту. Если у следующего шага `in`
  меньше, чем `out` предыдущего, кто-то фильтрует — это и есть «что куда зашло, что откуда вышло».
- `took` — время шага; итог — время всего прогона по стене.
- `calls` / `tokens` / `cost` — со всеми попытками и ветками; шаг без данных показывает прочерк, а не ноль.
- `output` — размер результата шага по контракту, а не всего транскрипта.

## Как посмотреть исходные данные, промпт и результат

Нажмите узел в **Pipeline** или кнопку **Inspect** в карточке шага. Вкладка **Step** показывает рядом
вход, сохранённый промпт или команду и выход. JSON/JSONL можно читать таблицей, искать записи и
читать выбранную строку отдельной карточкой **Record**. **Calls** показывает сохранённые вызовы внутри шага:
выберите вызов, чтобы увидеть его данные, промпт, ответ, модель, ошибку или предыдущую попытку.
**Files** открывает файлы и Markdown, **Checks** — независимые проверки Flora.

Чтобы такой разбор работал и у получателя `.flora-run`, конвейер должен сохранить сами входные
данные, промпты и ответы в объявленных артефактах. Flora не перехватывает автоматически все
внутренние запросы CLI. Если исходная история отсутствует, интерфейс сообщает об этом, а не
восстанавливает её по итоговым счётчикам. Формат записи и пример: [step-inspection.md](step-inspection.md).
